# 压缩后分叉

在 DSH Chat 记录的每个已落地的上下文压缩标记下，增加一行操作行。视觉与官方
Turn 结尾的图标行一致：复制、分支、用量、时间，但不含点赞/点踩。

## 为什么需要它

DSH 自带的“分支”动作挂在 Turn 结尾，传给 fork API 的是该 Turn 的
`turn/end` 序号。手动 `/compact` 发生在最后一个已完成的 Turn *之后*，所以那个
切点仍是压缩前的日志前缀：子会话重新展开的是这次压缩本该替换掉的完整历史。
会话列表菜单里的“分叉会话”确实会切到最新前缀（位于末尾的压缩会被包含），但它
不在对话流里，而且永远从当前末尾切。

本插件按 `compaction/end` 事件多加一个 Chat 行。在这个切点分叉时，子会话会继承
压缩事务与已落地的检查点，因此新会话从压缩后的上下文开始，就在压缩所在的位置。

## 行为

- 每次成功压缩（自动或手动）各一行，紧跟在压缩标记下面；压缩失败不出现。
- **复制**写入这次压缩的摘要正文（标记展开后显示的那段 Markdown），成功后图标
  短暂换成对勾。
- **分支**只保留图标，位置与官方 Turn 行一致。复用 Chat 视图自己的 fork 调用，
  因此子会话的标题、工作区归属和打开方式与内置分支动作完全一致；当前 Peer 对该
  会话没有 `session/fork` 权限时整行隐藏。
- **用量**显示摘要调用自己的「缓存读取 / 未缓存输入 / 输出」，配官方数据库图标。
  这段文字由 `dsh-statusbar-config` 统一格式化，与 Turn 胶囊同一个函数（见下）；
  未安装该插件时本行用完全相同的本地兜底格式。
- **用量弹窗**：点用量胶囊打开与官方「本轮用量」同款的弹窗——标题精确总数、提供方 /
  模型、缓存命中率、未缓存输入、缓存读取、缓存写入、输出。面板位于触发点上方并
  夹在视口内，随滚动/缩放重新定位，Esc 或点击外部关闭。
- **按官方规则显隐**：只有位于记录末尾的压缩操作行始终显示；一旦这次压缩后面还有
  别的对话内容（后续 Turn、新消息），它就和官方旧消息一样只在指针悬停或键盘焦点
  进入时淡入（80ms）。弹窗打开期间该行保持可见；无 hover 能力的设备上始终显示。
- **时间**是压缩结束时间，格式与官方消息时钟一致（当天 `HH:mm`，跨天用本地化
  日期模板）。
- 没有 Host 行为，也不写入会话事件：该行完全由已提交事件派生，重载与日志重放后
  仍然存在。
- 用量胶囊沿用官方窄屏行为：宽度低于 480px 时只留数据库图标。

## 与 dsh-statusbar-config 的集成

DSH 没有可独立复用的用量组件或 Slot，因此本行把自己的原始计数公布给状态栏插件
去格式化：

| 契约 | 方向 | 含义 |
| --- | --- | --- |
| `data-dfac-usage` | 本插件设置 | 对应 `compaction/summary` 事件的 seq |
| `data-dfac-cache-read`、`data-dfac-uncached-input`、`data-dfac-output` | 本插件设置 | 摘要调用的原始 buckets |
| `data-dfac-usage-label` | 本插件设置 | 被状态栏 CSS 隐藏的兜底文案元素 |
| `dsh-fork-row-usage`（冒泡事件） | 本插件在挂载时派发 | 通知状态栏插件格式化这一行 |
| `data-dsc-fork-row-usage`、`--dsc-fork-row-usage-label` | 状态栏插件设置 | 标记该胶囊并携带格式化后的文字 |

`dsh-statusbar-config` 挂载时扫描一次并监听该事件，因此先于此插件渲染出来的行也
会被覆盖。

## 限制

- 分叉点是**这次压缩的结束处**，不是记录当前的末尾。源会话在该压缩之后产生的
  内容不会进入子会话，这是有意为之。
- 压缩事件必须已经在已加载的记录页里；尚未分页加载到的旧压缩要等它加载后才会
  出现这一行。
- 弹窗展示的是 `compaction/summary` 事件里摘要调用自己上报的用量；该事件没有
  每次尝试的 route 列表与推理 token，因此弹窗不显示这两行。
- 悬停提示用的是原生 `title`，不是 App 的自定义 Tooltip 气泡：插件不允许加载
  `dsh-client-ui-primitives`，而复刻那套 portal/焦点实现超出了这一行的范围。
